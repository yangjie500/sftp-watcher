# Observability Setup

This document describes a local OpenTelemetry setup using:

- `otel-collector-config.yaml` as the collector configuration.
- A local shell script or command file to export collector environment variables
  and run the collector with Podman.

The current files are useful as a working reference, but they contain
environment-specific values. Treat them as examples and replace endpoints,
tenant names, credentials, and TLS settings for your environment.

## Flow

```text
sftp-watcher
  -> OTLP HTTP or gRPC
  -> local OpenTelemetry Collector
  -> debug exporter
  -> Grafana Cloud / Tempo / Loki
```

The app sends telemetry to the collector. The collector receives OTLP traffic on
ports `4317` and `4318`, then exports traces, metrics, and logs to the configured
backends.

## Application Settings

For local testing with the collector running on the same machine:

```env
SFTP_WATCHER_TELEMETRY_ENABLED=true
OTEL_EXPORTER_OTLP_ENDPOINT=http://localhost:4318
OTEL_EXPORTER_OTLP_PROTOCOL=http/protobuf
SFTP_WATCHER_TELEMETRY_VERIFY_TLS=true
```

Use `4318` with `http/protobuf`. Use `4317` only if the app is configured to use
OTLP gRPC.

If the collector is not available and you want to avoid export errors while
debugging other behavior:

```env
SFTP_WATCHER_TELEMETRY_ENABLED=false
```

## Collector Configuration

The local `otel-collector-config.yaml` currently defines:

| Section | Purpose |
| --- | --- |
| `receivers.otlp.protocols.grpc` | Receives OTLP gRPC on `0.0.0.0:4317`. |
| `receivers.otlp.protocols.http` | Receives OTLP HTTP on `0.0.0.0:4318`. |
| `processors.batch` | Batches telemetry before export. |
| `exporters.debug` | Prints received telemetry to collector logs. Useful for testing. |
| `exporters.otlphttp/grafana_cloud` | Sends OTLP telemetry to Grafana Cloud. |
| `exporters.otlphttp/tempo` | Sends traces to Tempo. |
| `exporters.otlphttp/loki` | Sends logs to Loki. |

The `service.pipelines` section wires the receiver, processor, and exporters:

| Pipeline | Exporters |
| --- | --- |
| `traces` | `debug`, `otlphttp/grafana_cloud`, `otlphttp/tempo` |
| `metrics` | `debug`, `otlphttp/grafana_cloud` |
| `logs` | `debug`, `otlphttp/grafana_cloud`, `otlphttp/loki` |

If you only want to confirm that the app is sending telemetry, keep the `debug`
exporter and temporarily remove external exporters that require credentials.

## Required Collector Environment Variables

The collector config references these environment variables:

| Variable | Example | Description |
| --- | --- | --- |
| `GRAFANA_CLOUD_OTLP_ENDPOINT` | `https://otlp-gateway-prod-ap-southeast-1.grafana.net/otlp` | Grafana Cloud OTLP endpoint. |
| `GRAFANA_CLOUD_INSTANCE_ID` | `<grafana-instance-id>` | Grafana Cloud instance ID. |
| `GRAFANA_CLOUD_API_TOKEN` | `<grafana-cloud-api-token>` | Grafana Cloud token. Keep secret. |
| `GRAFANA_CLOUD_AUTH` | Generated by script | Base64 value of `<instance-id>:<api-token>`. |
| `TEMPO_OTLP_ENDPOINT` | `https://tempo.example.com` | Tempo OTLP HTTP endpoint. |
| `LOKI_OTLP_ENDPOINT` | `https://loki.example.com/api/logs/v1/<tenant>/otlp` | Loki OTLP HTTP endpoint. |
| `LOKI_OAUTH_CLIENT_ID` | `<loki-client-id>` | OAuth client ID for Loki. |
| `LOKI_OAUTH_CLIENT_SECRET` | `<loki-client-secret>` | OAuth client secret for Loki. Keep secret. |
| `LOKI_OAUTH_TOKEN_URL` | `https://auth.example.com/realms/loki/protocol/openid-connect/token` | OAuth token endpoint for Loki. |

If one backend is not used, remove its exporter from the relevant pipeline and
remove the unused environment variables from the run command.

## Example Run Script

Create a local script such as `run-otel-collector.sh`. Do not commit real tokens.

```bash
#!/usr/bin/env bash
set -euo pipefail

export GRAFANA_CLOUD_OTLP_ENDPOINT="https://otlp-gateway-prod-ap-southeast-1.grafana.net/otlp"
export GRAFANA_CLOUD_INSTANCE_ID="<grafana-instance-id>"
export GRAFANA_CLOUD_API_TOKEN="<grafana-cloud-api-token>"

export TEMPO_OTLP_ENDPOINT="https://tempo.example.com"

export LOKI_OAUTH_CLIENT_ID="<loki-client-id>"
export LOKI_OAUTH_CLIENT_SECRET="<loki-client-secret>"
export LOKI_OAUTH_TOKEN_URL="https://auth.example.com/realms/loki/protocol/openid-connect/token"
export LOKI_OTLP_ENDPOINT="https://loki.example.com/api/logs/v1/<tenant>/otlp"

export GRAFANA_CLOUD_AUTH="$(
  printf '%s:%s' \
    "$GRAFANA_CLOUD_INSTANCE_ID" \
    "$GRAFANA_CLOUD_API_TOKEN" |
  base64 |
  tr -d '\n'
)"

podman run --rm \
  --name otel-collector \
  -p 4317:4317 \
  -p 4318:4318 \
  -e GRAFANA_CLOUD_OTLP_ENDPOINT \
  -e GRAFANA_CLOUD_INSTANCE_ID \
  -e GRAFANA_CLOUD_API_TOKEN \
  -e GRAFANA_CLOUD_AUTH \
  -e TEMPO_OTLP_ENDPOINT \
  -e LOKI_OAUTH_CLIENT_ID \
  -e LOKI_OAUTH_CLIENT_SECRET \
  -e LOKI_OAUTH_TOKEN_URL \
  -e LOKI_OTLP_ENDPOINT \
  -v ./otel-collector-config.yaml:/etc/otelcol-contrib/config.yaml:Z \
  otel/opentelemetry-collector-contrib:latest \
  --config=/etc/otelcol-contrib/config.yaml
```

The `:Z` mount option is for SELinux environments. Remove it if your container
runtime does not support it.

## Test Locally

Start the collector:

```bash
bash ./run-otel-collector.sh
```

In another shell, run the app with telemetry pointing to the local collector:

```bash
export SFTP_WATCHER_TELEMETRY_ENABLED=true
export OTEL_EXPORTER_OTLP_ENDPOINT=http://localhost:4318
export OTEL_EXPORTER_OTLP_PROTOCOL=http/protobuf

sftp-watcher --env-file .env
```

Expected checks:

- The collector starts without configuration errors.
- The collector logs show `debug` exporter output when the app emits traces or
  logs.
- The app does not log OTLP export connection errors.
- The external backend receives traces and logs if those exporters are enabled.

## Common Adjustments

If the collector starts but the app cannot export telemetry, confirm:

- The app uses `http://localhost:4318` when running on the same host as the
  collector.
- The app uses the Kubernetes service name instead of `localhost` when running
  inside a cluster.
- `OTEL_EXPORTER_OTLP_PROTOCOL=http/protobuf` is set when using port `4318`.
- Firewalls or container networking allow access to the collector port.

If the collector fails to export to an external backend, confirm:

- Endpoint URLs are correct for the backend and tenant.
- Required credentials are present in the collector environment.
- TLS verification settings match the backend certificate setup.
- The exporter is included in the correct `service.pipelines` entry.

## Security Notes

Do not commit real API tokens, OAuth secrets, or generated auth headers. If a
token was committed or shared accidentally, rotate it.

For production, prefer Kubernetes Secrets, a secret manager, or another approved
secret injection mechanism instead of hardcoded shell exports.
