# Bundle Format

The watcher processes downloaded tarball bundles and publishes extracted release
content to Git.

## Filename Metadata

The filename must contain at least these metadata fields:

```text
{tenant_id}-+{project_name}-+{project_version}.tar.gz.bundle
```

Example:

```text
mario-+frontend-+22.0.7-+20241028T115959.tar.gz.bundle
```

The application extracts the first three fields using `-+` as the separator:

```json
{
  "tenant_id": "mario",
  "project_name": "frontend",
  "project_version": "22.0.7"
}
```

Additional filename fields after `project_version` are allowed and ignored by
the bundle preparation flow.

The separator is configurable:

```text
BUNDLE_FILENAME_METADATA_SEPARATOR=-+
```

## Outer Bundle

The outer `.bundle` file must be a tar-compatible archive.

If present, a signature file may use one of these suffixes:

```text
.sig
.signature
.asc
```

When a signature file is present, the nested tarball must be in the same
directory as the signature file. The signature is used as the anchor for finding
the payload tarball.

Example outer bundle layout:

```text
payload/release.tar.gz
payload/release.tar.gz.sig
```

If no signature file is present, the outer bundle is accepted only when it
contains exactly one supported nested tarball. Multiple tarball candidates are
rejected so the app does not accidentally process the wrong payload.

The extractor rejects unsafe archive paths that attempt to write outside the
temporary extraction directory.

## Nested Tarball

The nested tarball is extracted into the publish working directory. Its content
is the content that will eventually be pushed to Git after filtering and
manifest generation.

Expected content usually includes:

```text
charts/
metadata/
```

Container image folders are removed before publish.

## TIMESTAMP.json

The processor tries to extract optional timing metadata from `TIMESTAMP.json`.

Expected keys:

```json
{
  "TIMEDATE": "20241028T115959",
  "SIZEOFFILE": "2048 KB"
}
```

`TIMEDATE` must use this format:

```text
YYYYMMDDTHHMMSS
```

`SIZEOFFILE` currently expects `KB` as the unit.

If this metadata extraction fails, the processor logs a warning and continues.
The bundle can still be published.

## Container Image Removal

Before publishing, the app removes directories matching:

```text
images
image
container-images
oci-images
```

This list is configurable with:

```text
BUNDLE_CONTAINER_IMAGE_DIRS=images,image,container-images,oci-images
```

The app removes the whole matching directory, not only files with image archive
extensions.

## Helm Chart Expansion

Packaged Helm chart archives ending in `.tgz` are expanded before publishing if
they contain a `Chart.yaml`.

The original `.tgz` package is removed after expansion.

Non-Helm `.tgz` files are ignored.

## release.json

Before publishing, the app writes `release.json` at the root of the publish
directory.

Example:

```json
{
  "tenant_id": "mario",
  "project_name": "frontend",
  "project_version": "22.0.7",
  "remote_tarball_path": "upload/mario-+frontend-+22.0.7-+20241028T115959.tar.gz.bundle"
}
```

This file is generated by the watcher. It should not be required inside the
incoming tarball.
